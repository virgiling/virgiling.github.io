# Markdown 友链与 RSS 近况

友链沿用 `content/link.md` 的发布标记、正式地址和评论身份。Markdown 中使用普通表格，在 Obsidian 或 GitHub 中无需专用组件；Astro 将表格转换为友链卡片，其他正文保留。页面不显示通用文章抬头与元信息，卡片不加额外标题，只在订阅列表上方保留一个一级标题「近况」。列表采用紧凑单行「作者－标题　日期」，日期靠右；长作者名和标题省略显示，链接仍保留完整文本与悬停提示。

## 格式

```markdown
| 链接 | 简介 | 头像 | RSS |
| --- | --- | --- | --- |
| [Ada](https://notes.example.com/) | 编译器研究员，喜欢徒步 | ![Ada](https://notes.example.com/avatar.png) | [RSS](https://notes.example.com/rss.xml) |
| [Lin](https://garden.example.com/) | 数学系学生，业余写程序 | | |
| [Sam](https://profile.example.com/) | 自由职业开发者 | | - |
```

- 必填 **链接**：标准 Markdown 链接，链接文字用作朋友的显示名。可增加 **姓名**、**昵称** 或 **名称** 列覆盖显示名。
- **简介**（也可写作 **个人简介**）介绍朋友本人，而不是网站内容，直接使用表格中的文字，不从网站抓取或生成介绍。
- **简介**、**头像**、**RSS** 均可省略。已有的「简介 | 链接」两列表格兼容，无需先迁移。
- 头像只使用表格明确填写的 Markdown 图片、普通链接或 URL；缺列、空白或 `-` 时显示名字首字，不寻找头像或 favicon。填写后由浏览器直接请求，不在构建期下载或转码。
- RSS 只请求表格明确填写的 HTTPS 地址；缺列、空白或 `-` 均表示没有订阅，不访问首页、不探测常见路径，也不复用旧自动发现结果。以后填写 RSS 地址才会开始同步。
- 同一链接去重，卡片按 Markdown 顺序展示。只有发布且非 unlisted 的 `link.md` 会产生友链与订阅数据；不要把私有订阅令牌写入公开表格。

## 同步和展示

构建阶段仅同步已填写地址的 RSS 2.0 / Atom，页面没有跨域 RSS 请求，也不依赖浏览器 CORS 代理。每个源最多保留 12 篇有有效标题、日期、HTTPS 链接的文章；合并后按日期倒序、URL 去重，页面合计最多显示 10 篇（不是每位朋友 10 篇）。正文 HTML 不嵌入本站。

本地快照位于 `.astro/friends/`，仅在构建或主动同步时读取，六小时内复用；不会启动后台刷新。可主动刷新后构建：

```sh
bun run friends:sync
bun run build
```

GitHub Pages 发布工作流仅在 `main` 收到推送时触发一次，不设置定时、手动或其他工作流完成后的触发器。构建时刷新订阅并生成一份静态近况快照，不为快照另行安排任务。页面保留该次构建结果，不承诺实时更新。工作流只缓存规范化的公开订阅快照，不缓存私有内容源或 Astro 编译输出。

每次最多同时访问两个已配置的订阅，单个朋友的读取预算为 20 秒、单请求 6 秒、响应不超过 2 MiB、重定向不超过三次。只请求公开 HTTPS 地址，检查 DNS 并固定实际连接地址，拒绝本地/私有地址及 XML DTD。单个源失败不会阻止站点构建：同一显式 RSS 地址有旧快照时显示旧文章并注明，首次失败则保留友链卡片、不捏造更新。删除 RSS 地址后不再显示其缓存文章。

设计参考 [Navfolio Friend Circle](https://github.com/navfolio/friend-circle-sync) 的构建侧同步方式；RSS/Atom 解析使用 [rss-parser](https://github.com/rbren/rss-parser)。
