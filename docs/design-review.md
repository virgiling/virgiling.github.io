# 从 Quartz 到 Astro：把博客重新做成自己的样子

> 从笔记发布规则、内容编译到阅读体验，记录这次从 Quartz 迁移到 Astro 的主要设计取舍。

## 1. 为什么离开 Quartz

我需要的不是一个可分发主题，而是一套适合自己写作与阅读习惯的博客。

Quartz 已经解决了很多笔记发布的问题：双链、预览、搜索、反向链接和知识图谱。离开它，并不是证明这些能力不好，也不是得出了“Quartz 一定更慢”的性能结论。真正促使我迁移的，是不想继续围绕 Quartz v5 的插件体系维护自己的站点。

但换框架不能只换一层皮肤。旧站已经形成了一组重要约定：什么内容允许公开、文章地址怎样生成、双链怎样解析、评论关联到哪一篇文章。这些是迁移必须保留的契约；框架只是它们的一种实现。

因此，新站的目标不是“再造一个 Quartz”，而是拆开两件事：

- **内容编译**负责理解笔记、处理发布边界和知识关系。
- **网站框架**负责路由、静态页面、资源与开发环境。

我选择 Astro 做后者，把前者留在本站的 TypeScript 模块中。这里没有插件市场、主题适配器或自动发现机制，也不要求把 Markdown 改写成 MDX。

## 2. 先保住内容，而不是先重做页面

### 两个仓库，各自保留历史

主站代码对应 `virgiling/virgiling.github.io`，内容对应 `virgiling/blog_content`。后者作为 Git submodule 挂载在 `content/`。

构建输入固定为 `content/` 中记录的版本。主仓库记录内容 commit，生产构建要求 gitlink 与内容 HEAD 一致、工作树干净，而不是在构建时自动跟随最新分支。这样，每一次页面输出都有明确、可复现的输入。

### 公开与可发现不是同一件事

我保留了旧站的显式发布规则：

| 状态 | 页面是否生成 | 是否进入发现入口 |
|---|---|---|
| `publish:true`，非 unlisted | 是 | 是 |
| `publish:true` 且 `unlisted:true` | 是，可直链访问 | 否 |
| 缺少 publish 或 `publish:false` | 否 | 否 |

`draft` 是编辑状态，不能代替发布许可。unlisted 也不是访问控制：知道地址的人仍可访问，但它不应出现在列表、搜索、全局图谱、RSS 或 sitemap 中。

实现中将可生成页面集合记作 **P**，可发现集合记作 **D**。发现数据只消费 D；允许直链的页面属于 P。硬忽略目录和符号链接拒绝先于正文解析，附件只通过允许的引用集合进入输出，不能把整个内容仓库直接复制到公开目录。

这条边界同样适用于未来的地图：有坐标不代表同意公开。没有公开地点时，足迹页显示真实空状态，而不是用未发布笔记填满地图。

### 地址与评论是迁移资产

普通文章沿用来源路径形成的 extensionless URL，目录导读保留末尾 `/` 和 `index.html`。Astro 的 file-format 输出会扁平化部分目录索引，因此构建收尾会按真实导读路由恢复目录结构，而不是顺手重写全部地址。

giscus 使用 `mapping="specific"`，以**正式站点上的文章完整 URL**作为讨论键。localhost、开发端口和 `/preview/` 不进入这个键；本地页面也可以加载真实评论。否则，“本地能看到评论”和“保住旧讨论关联”会变成两件互不相干的事。

源路径保留不等于所有历史 alias/permalink 已经完成重定向或线上讨论核对。后者仍应按真实旧地址清单单独处理，不用一个构建成功来代替。

## 3. Astro 是外壳，笔记编译才是核心

当前技术栈由锁文件固定：Astro 7.3.5、Node 24.19.0、Bun 1.3.11，配合 TypeScript、unified/remark/rehype、Shiki、MathJax、Tailwind CSS、Motion 和 FlexSearch。精确依赖以 `package.json`、`bun.lock` 为准，不长期追随 `latest`。

编译流程分成两遍：

```text
content/ 的固定提交
  → 硬忽略、发布选择、资源边界
  → 第一遍：文档身份、元数据、AST、标题/块索引、别名和原始链接
  → 第二遍：解析跨文档目标、展开允许的嵌入、重绑定资源和脚注
  → 消毒后的 HTML + TOC + 反链 + 图数据 + 搜索数据
  → Astro 静态页面与按需客户端增强
```

这样做，是为了避免正文、搜索和图谱各自猜测链接。同名目标不能悄悄选择第一个；未公开目标不能因为被引用就自动发布；嵌入后的链接也不能全部算成宿主作者新写下的关系。

当前已实现 CommonMark/GFM 基础、双链与别名解析、标题/顶层块链接、整篇/章节/块嵌入、循环保护、脚注、标签、Callout、图片说明、Shiki 和构建期 MathJax。Callout 支持 13 类、27 个标识，保留折叠与嵌套。`poetry` 作为 Plaintext 代码框，保留空白、换行和字面内容；不引入自动 bibliography/CSL/BibTeX。

原生 HTML 经过白名单消毒，危险 URL、脚本和事件属性不会因为“编辑器里能显示”就进入公开页面。

这仍不是完整的 Obsidian 运行时。复杂 OFM 边界、Mermaid 渲染、Bases 解释器、Canvas、查询嵌入，以及任意社区插件，都需要自己的范围与用例。当前不能把普通代码块或提示信息称为已经支持了对应功能。

## 4. 从设计原型到真正的阅读界面

早期原型用来确认阅读秩序。方向确定后，页面通过真实 Astro 路由、内容与共享组件实现，避免让静态展示和实际阅读体验成为两套不同的东西。

### 页面先为阅读服务

本站保持浅色，不跟随系统深色，也没有主题切换。顶层导航固定为“主页、文章、足迹、关于”，文章有自己的地址。

桌面采用宽正文与右侧辅助栏，窄屏改为单栏。主页右栏依次是最近更新与热力图、关系图谱、大纲；其他阅读页依次是图谱、大纲、反向链接。最近更新只显示一篇，标题与日期同排。热力图保留日期信息，不增加装饰性的说明和图例。

主页与关于直接来自内容仓库的 `index.md`、`about.md`。具体文章和目录导读显示面包屑，名称优先使用公开目录索引的标题；主页、关于和列表页不强加面包屑。

中文正文采用霞鹜文楷轻便版，英文采用 Linux Biolinum，代码优先设备上的 Monaco。阅读日期与正文同字号，颜色较浅；Biro 用于欢迎语和阅读元信息。样式以 Tailwind 的 tokens、工具与语义组件为主，不启用 Preflight，不扫描内容库提取 CSS，也不把 Tailwind 本身当作性能优化。

### 目录不是另一种标签列表

归档按真实目录递归分组，不按 tag 复制文章。一级目录没有额外边框，卡片保留圆角与层次；卡片显示标题、摘要、创作日期和标签，不使用封面。摘要优先取 description，否则取正文首句。

卡片组支持鼠标悬停展开、移开收起，同时保留键盘与触屏路径；没有独立的展开按钮。标签页复用卡片，桌面双列、窄屏单列。标签较多时调整日期位置，而不是让摘要区域不断挤压。

MoC 是“内容地图”笔记，也是目录的入口。构建模块把一级目录与唯一匹配的 `*-toc.md` 对应：只接受公开、可发现的页面；同名歧义不猜测，深层或未匹配的 MoC 仍按普通文章处理。

映射成功后，目录标题成为通往原 MoC 的原生链接，不再额外摆一张重复卡片。MoC 的原页面、评论、搜索与图谱身份都保留。这样，每篇内容在归档里只有一个入口，而不是靠隐藏文章来消除重复。

当前页首是“142 则笔记，48 个主题，慢慢生长。”：138 张卡片加 4 个 MoC 标题入口，主题数只计显式标签，不把补出的祖先标签也算进去。

### 交互不能抢走阅读位置

大纲不仅高亮当前标题，还会让被裁切的活动条目重新可见：先调整内部目录滚动区，再检查外层侧栏或移动弹窗。这里采用即时、最小的可见性补位，不滚动正文、不抢键盘焦点。

链接预览保留原生 `<a>` 导航，通过 Floating UI 处理边缘定位；旁边的图钉用于固定摘要预览。当前预览是摘要，不冒充全文或预览内锚点导航。

所有有时长的自有动效都经过共享 Motion，包括卡片、大纲标记、预览、图谱与灯箱。直接拖动坐标、滚动进度和即时可见性校正不是时间插值，不为了统一工具而人为加动画。取消、销毁和运行时 reduced motion 是同一份交互契约的一部分。

## 5. 图谱：复用成熟力学，但不照搬整个插件

局部图回答“这篇笔记直接联系着谁”，全局图回答“整个知识库如何连接”。两者不能只用同一张图换一个尺寸。

### 严格的一跳局部图

局部图只包含当前笔记、直接出链/反链和本页显式标签。不自动加入邻居的标签、标签祖先、同标签文章或二跳笔记；保留这些节点之间真实存在的边，不编造关系。

初始布局在服务端用 D3 计算 180 ticks，再生成 300×250 的 SVG。当前笔记初始位于 `(150,125)`，普通节点半径 5.5，当前点 7，命中圈 12。局部图不显示说明、缩放工具栏和图例，只保留全局图入口；无脚本时仍可使用节点链接。

交互时可以拖动页面、标签和当前节点，**不能拖背景平移整张图**。滚轮/双指缩放保留，双指中点移动不平移；聚焦节点时方向键移动该点，Enter 正常导航，Home/0 恢复初始位置与视口。

**拖动只是临时位移，图心不变**。当前笔记松手后平滑回中心，邻居重新平衡，不要求每个点回到拖前的精确坐标；缩放不被重置。这样既能探索连线，也不会因一次拖动失去当前笔记的视觉中心。

实现继续使用 D3 的向心力：一个独立粒子带动当前锚点返回，与邻域模拟共享 Motion 时钟，不手写补间。重新抓取可中断返回，后台暂停，reduced motion 直接求终态，销毁后不再更新。懒加载晚到时，也不能把已经拖动的坐标误认为图心。

### 自然分布的全局图

全局图只消费 D，保留页面链接、标签成员和标签父子关系，但不让标签树决定几何位置，也不把文章排成网格。使用 Canvas 绘制，模块与数据在打开或交互意图时才准备；不在首屏抓取完整图数据。

核心来自 `starlight-site-graph@0.5.0` 的 D3 force/drag 适配，保留 MIT 署名；不是把 Starlight、Pixi、GSAP 和预取体系整体搬进来，也不是重写力学引擎。早期插件配置合并遇到问题后，继续修补和验证数据消费，比看到一次报错或一个较大的包体就放弃复用更合理。

全局节点按独立邻居数增长，互链和重复边不重复计数，自环不计：

```text
radius = min(12, 5 + 1.5 × sqrt(degree))
```

半径限制在 5–12，碰撞、命中与文字偏移随之调整；当前节点用颜色区分，不突破上限。这个尺寸规则不影响局部图。

两种图共用缩放显字规则：1 倍及以下隐藏普通短标题，1–1.9 倍逐渐显露，1.9 倍后全部显示；当前、悬停、聚焦以及局部拖动节点保留反馈。完整名称仍可访问。

全局保留图例、必要的缩放/复位/关闭与错误状态，不显示页面/标签列表或操作说明。全局背景可以平移，节点拖动带动邻域；这与局部图的禁止背景平移是两个明确约定。

D3 自身的模拟时钟停止，由 Motion 有界推进，重热后最多 180 ticks。源码对照也揭示了边界：[starlight-site-graph](https://github.com/fevol/starlight-site-graph/blob/fed9ce0b3aa160255a673aa76aeea17166dcceb9/packages/starlight-site-graph/components/graph/simulator.ts) 与 [Quartz](https://github.com/jackyzha0/quartz/blob/d25a6eabf96751ffca56f8a8139272def7a65041/quartz/components/scripts/graph.inline.ts) 都在松手时解除 `fx/fy`，但并不保证每个点恢复旧坐标。当前笔记精确回图心是本站补充的约束，不是虚构的插件开关。

## 6. 图片与字体：布局正确不代表资源正确

### 自定义 Markdown 输出需要接上图片管线

自定义 unified 编译后用 `set:html` 输出正文，不会自动获得 Astro 图片组件的全部优化。仅设置 `loading="lazy"`，既不能防止大图溢出，也不会生成更合适的资源。

因此，消毒后的正文另外经过 Astro 原生 `getImage()` / Sharp：保留作者尺寸、alt、图注和原有图片链接，按比例生成 WebP 候选，写入真实尺寸、srcset 与 sizes。默认不裁剪、不放大，GIF 保留动画；远程来源使用明确允许列表和有界元数据请求。准备失败保留原图，但不能承诺后续转换在任何离线环境下都成功。

这里还出现过“声明 400w，实际只有 399 像素”的舍入错误。修正为按宽度等比缩放后，验证器逐一读取实际图片尺寸，再检查 srcset 描述符，而不是只看 HTML 写得像不像。

原图放大采用 medium-zoom 的 pure 入口。保留成熟库的几何和克隆机制，通过锁定补丁把开合交给 Motion，补齐关闭中断、加载超时、焦点与清理。已有作者链接不劫持，修饰键和无脚本路径仍可打开原图。

### 缺字不是补两字就结束

旧的小字体子集没有覆盖“旅途还在继续”中的部分字符，静态字体又被错误声明成可变字重。只补两个字，会把问题推迟到下一篇文章。

现在字体输入统一放在 `assets/fonts/`：

| 输入 | 用途与处理 |
|---|---|
| LXGW WenKai Lite 1.522 Regular | CJK，固定 OFL 输入，生成分片 |
| Linux Biolinum O Regular / Bold | Latin，固定 OFL 输入，分别生成分片 |
| Biro Script Plus 原始 WOFF2 | 作者提供，保持 284,772 B 与 OpenType，不重新子集化 |

CJK 与 Latin regular 如实声明 400，Latin bold 声明 700；没有额外提供真正的中文粗体，明确需要粗体的中文仍可能由浏览器合成。足迹页使用正常字重，而不是借系统缺字回退形成混杂样式。

字体制作参考 [astro-navfolio 的 UI 子集脚本](https://github.com/dodolalorc/astro-navfolio/blob/v1/scripts/fonts/subset-ui-font.ts)。流程是：固定源文件及 SHA256，使用锁定的 FontTools/Brotli，扫描 UI 源目录生成优先子集，再生成完整源字表的 Unicode 分片。完整覆盖不依赖当前文章里恰好出现了哪些字符。

这保留了源字体支持的 25,598 个 CJK 字符、2,400/2,539 个 Latin 字符。CSS 的声明顺序与实际 cmap 一起验证，避免某个 unicode-range 声称接管字符却没有字形。源字体之外的 Unicode 仍需要系统回退；完整 cmap 也不等于已经验证所有跨片 shaping 或浏览器字体选择。

字体分片不是免费优化。当前 OFL 产物为 167 个 WOFF2、7,619,272 B，其中三个 UI 片合计 124,504 B；最大一片 92,424 B。加上原始 Biro 为 7,904,044 B。分片重复表、压缩边界及 UI 优先覆盖都会增加存储，**UI 字节不等于一页的字体下载量**。

生成目录只需要当前 CSS/manifest 引用的 167 个 WOFF2，加上 CSS 和清单共 169 个文件。分片分别承载不同字重与字符范围；UI 与完整字表的部分字符重叠是加载策略，不能简单按字符重复去删除，更不能为了减少文件数变成首屏加载完整大字库。

`fonts:clean` 是显式维护命令：先检查清单、CSS、文件哈希与路径，再删除无引用产物；不在 dev/build 中自动清理旧地址，避免破坏正在使用旧 CSS 的页面。清理时不与字体生成并行，旧页面应重新打开。

Biro 直接使用原始 WOFF2，不参与 OFL 子集流程。它不属于 OFL，使用时需要相应的 Webfont 许可。

## 7. 真正的开发服务，也是验证对象

有一次，全局图 JSON 和入口脚本都是 200，页面却仍然打不开图。原因在入口引用的 Vite 预优化依赖：它们返回 `504 Outdated Optimize Dep`。只检查 JSON，或者在 Node 中从 node_modules 重新打包，都可能绕过这条真正失败的路径。

现在开发缓存按命令、端口和 base 隔离，避免并行开发和验证进程互相覆盖预优化依赖。内容快照与派生数据按版本共享，失败允许重试；内容更新不仅使快照失效，也通知 Astro 清理路由 props，避免拿旧页面数据重新渲染。

测试覆盖分成几层：

- Node fixtures 检查发布边界、OFM、链接、图谱、交互状态与清理。
- 编译和静态产物检查验证路由、片段、资源、字体哈希、图片像素与预算。
- 独立 HTTP 检查验证深链、资源 MIME、二进制与 404。
- 开发检查读取真实 Vite ESM 和首页 SVG，通过默认懒加载入口在 Node DOM/Canvas 边界执行图谱逻辑，检查松手回中心、暂停恢复与 reduced motion，而非绕过实际模块请求。

这些检查不覆盖真实浏览器的渲染、输入与辅助技术行为。LCP、INP、帧率、触屏和屏幕阅读器体验需要各自的实测，不能从 Node 或 HTTP 检查中推断。

资源预算也只回答有限问题：首屏 JS gzip 不超过 20 KiB，共享 CSS gzip 不超过 12 KiB；UI 字体不超过 256 KiB、单片不超过 128 KiB、完整 OFL 存储不超过 8 MiB，Biro 单列。旧的“其他字体总量 256 KiB”已被完整字表方案替代，不能继续声称满足它。没有用包体较小证明“更快”，也不把静态样本的历史性能分数套到真实站点上。

测试还需要贴合交互意图。例如，局部图的回归既要验证节点可以拖动，也要验证当前节点松手后回到固定图心；只验证前半段，无法保证完整行为。

## 8. 一个可以继续生长的博客

当前内容生成 202 个 HTML 页面：144 个公开阅读页、55 个标签页，以及归档、足迹和 404。静态输出让内容编译与页面交付分开：构建环境需要源码、锁文件、字体输入和固定内容版本，静态服务器只需要 `dist/`。内容源库、构建缓存和原始 TTF/OTF 不属于静态发布目录。

这套实现仍有明确的能力范围：Bases/地图、Mermaid 渲染、全文预览、更完整的 OFM 与历史别名重定向，都还有继续完善的空间。新增能力应接入同一套文档身份、发布选择与资源管线，而不是再建立一套互相矛盾的解析规则。

最后留下的不是一套更庞大的框架，而是一组更清楚的职责：内容仍由自己的笔记库决定，成熟库解决成熟问题，本站代码只承担真正需要自己决定的部分。
