# 从 Quartz 到 Astro：把博客重新做成自己的样子

> 从笔记发布规则、内容编译到阅读体验，记录这次从 Quartz 迁移到 Astro 的主要设计取舍。

## 1. 为什么离开 Quartz

我需要的不是一个可分发主题，而是一套适合自己写作与阅读习惯的博客。

Quartz 已经解决了很多笔记发布的问题：双链、预览、搜索、反向链接和知识图谱。离开它，并不是证明这些能力不好，也不是得出了“Quartz 一定更慢”的性能结论。真正促使我迁移的，是不想继续围绕 Quartz v5 的插件体系维护自己的站点。

但换框架不能只换一层皮肤。旧站已经形成了一组重要约定：什么内容允许公开、文章地址怎样生成、双链怎样解析、评论关联到哪一篇文章。这些是迁移必须保留的契约；框架只是它们的一种实现。

因此，新站的目标不是“再造一个 Quartz”，而是拆开两件事：

- **内容编译**负责理解笔记、处理发布边界和知识关系。
- **网站框架**负责路由、静态页面、资源与开发环境。

我选择 Astro 做后者，把前者留在本站的 TypeScript 模块中。这里没有插件市场、主题适配器或自动发现机制，也不要求把 Markdown 改写成 MDX。

## 2. 先保住内容，而不是先重做页面

### 两个仓库，各自保留历史

主站代码对应 `virgiling/virgiling.github.io`，内容对应 `virgiling/blog_content`。后者作为 Git submodule 挂载在 `content/`。

构建输入固定为 `content/` 中记录的版本。主仓库记录内容 commit，生产构建要求 gitlink 与内容 HEAD 一致、工作树干净，而不是在构建时自动跟随最新分支。这样，每一次页面输出都有明确、可复现的输入。

### 公开与可发现不是同一件事

我保留了旧站的显式发布规则：

| 状态 | 页面是否生成 | 是否进入发现入口 |
|---|---|---|
| `publish:true`，非 unlisted | 是 | 是 |
| `publish:true` 且 `unlisted:true` | 是，可直链访问 | 否 |
| 缺少 publish 或 `publish:false` | 否 | 否 |

`draft` 是编辑状态，不能代替发布许可。unlisted 也不是访问控制：知道地址的人仍可访问，但它不应出现在列表、搜索、全局图谱、RSS 或 sitemap 中。

实现中将可生成页面集合记作 **P**，可发现集合记作 **D**。发现数据只消费 D；允许直链的页面属于 P。硬忽略目录和符号链接拒绝先于正文解析，附件只通过允许的引用集合进入输出，不能把整个内容仓库直接复制到公开目录。

这条边界同样适用于足迹地图：有坐标不代表同意公开。地图查询与文件属性查找只消费 D，没有有效的公开地点时显示真实空状态，而不是用未发布或 unlisted 笔记填满地图。

### 地址与评论是迁移资产

大纲中的标题使用双链的显示名（如 `[[课程路径|CMU 15-213]]` 显示为 `CMU 15-213`），代码中的字面语法不替换；标题 ID 继续沿用历史 slug，避免改变已有深链。标题显示名和层级路径参与片段解析，但不以显示文字重写旧锚点。

普通文章沿用来源路径形成的 extensionless URL，目录导读保留末尾 `/` 和 `index.html`。Astro 的 file-format 输出会扁平化部分目录索引，因此构建收尾会按真实导读路由恢复目录结构，而不是顺手重写全部地址。

文章的 `og:title` 只使用文章标题：优先取非空的 YAML `title`，缺失时回退到不含 `.md` 的文件名；不追加文件名、目录或站点名称。文章列表、标签等系统页面使用页面标题。页面内的展示标题与带站点名称的 `<title>` 保持不变。

giscus 使用 `mapping="og:title"` 和 `data-strict="1"`，以文章标题的 SHA-1 匹配讨论正文中的标记。显式标题不变时，移动目录、重命名文件或更换域名不改变关联；但修改标题、或修改作为标题兜底的文件名，仍需要迁移匹配标记。开启评论的页面必须具有唯一标题，静态产物检查会拒绝重名，避免不同文章共用讨论。

历史讨论迁移保留原 Discussion 编号、评论和回复，在原正文中添加当前标题的 SHA-1 标记；保留旧 URL 的标记可以兼容尚未切换配置的旧页面。讨论标题可同步为文章标题。`giscus:backlink` 仍使用正式站点的文章完整 URL，localhost、开发端口和 `/preview/` 不进入回链；它用于返回文章，而不再作为评论匹配键。

源路径保留不等于所有历史 alias/permalink 已经完成重定向或线上讨论核对。后者仍应按真实旧地址清单单独处理，不用一个构建成功来代替。

## 3. Astro 是外壳，笔记编译才是核心

当前技术栈由锁文件固定：Astro 7.3.5、Node 24.19.0、Bun 1.3.11，配合 TypeScript、unified/remark/rehype、Shiki、MathJax、Tailwind CSS、Motion 和 FlexSearch。精确依赖以 `package.json`、`bun.lock` 为准，不长期追随 `latest`。

编译流程分成两遍：

```text
content/ 的固定提交
  → 硬忽略、发布选择、资源边界
  → 第一遍：文档身份、元数据、AST、标题/块索引、别名和原始链接
  → 第二遍：解析跨文档目标、展开允许的嵌入、重绑定资源和脚注
  → 消毒后的 HTML + TOC + 反链 + 图数据 + 搜索数据
  → Astro 静态页面与按需客户端增强
```

这样做，是为了避免正文、搜索和图谱各自猜测链接。同名目标不能悄悄选择第一个；未公开目标不能因为被引用就自动发布；嵌入后的链接也不能全部算成宿主作者新写下的关系。

未公开、不存在、歧义或章节缺失的内部目标保留作者写下的显示文字：双链沿用别名或原目标文字，Markdown／引用式链接保留标签及其行内格式，不再替换为「该内容未公开或不可用」。正文链接和旁边的 popout 图钉均使用原生、base-aware 的 404 页面链接；图钉不是无效的预览按钮，不请求未知目标，也不生成对应的图谱边或预览记录。缺失嵌入只保留作者的引用名称，不获取目标标题或正文；构建期已知不可用的本地图片（包括双链、Markdown、引用式与原生 HTML 图片）直接隐藏，不插入提示语、文件名或 404 图钉；作者写下的独立 caption 保持可见，正常图片及显式附件链接不受影响。远程图片不由构建器请求或探测可用性。有效公开链接继续提供全文预览；unlisted 的显式直链与禁止从公开页嵌入的边界不变。

当前已实现 CommonMark/GFM 基础、双链与别名解析、标题/顶层块链接、整篇/章节/块嵌入、循环保护、脚注、标签、Callout、图片说明、Shiki 和构建期 MathJax。Callout 支持 13 类、27 个标识，保留折叠与嵌套。`poetry` 作为 Plaintext 代码框，保留空白、换行和字面内容。

文献引用固定读取 `content/ref.bib`，使用 `[@citekey]`、`[see @key1; @key2, pp. 4–5]`。`@benrbray/remark-cite` 负责 Markdown 语法节点，Citation.js 解析 BibTeX/BibLaTeX，`rehype-citation` 与自定义 CSL 在构建期生成引用及文献条目。插件的 Bun 补丁只为 Node 入口增加内存 CSL-JSON 输入和内联 CSL，避免每篇文章重复读取数据库、临时文件以及任意远程文献请求；不引入客户端文献引擎。原生 HTML、已有链接、代码、数学、转义文本和裸 `@name` 不作为引用。未知 key 保留整组作者文本并给出构建诊断，不阻断后续有效引用。

每篇有有效引用的文章自动生成二级 `References` 章节并进入目录，仅列该文实际引用项，按首次引用顺序排列；重复引用去重，允许的嵌入与脚注共享该文列表。末尾已有的 `## References` 标题会复用，否则创建不冲突的标题 ID；文献列表位于脚注区之前。文内标签使用原生 fragment 链接，不创建文章关系、图谱边或 popout 按钮；全文预览复用现有 ID 重映射与局部定位。

样式依据 [Slides-Template 的 biblatex 配置](https://github.com/virgiling/Slides-Template/blob/6aac897cb251e1b41abf6e0ca648475819a44300/latex/example.tex)：单作者姓氏前三字符、多作者前三位姓氏首字符、超过三位加 `+`，后接年份末两位，例如 `[Lam94]`、`[VSP+17]`。同一文章内标签冲突预先加 `a`、`b` 等后缀；无作者时回退编辑者或标题，无年份用 `nd`。文献作者名使用首字母缩写，最多列三位后接 et al.，保留标题、刊物/会议、卷期、出版信息和页码；不显示 DOI、ISBN、URL、eprint。会议 booktitle 采用弱化色斜体，字号和间距沿用网页阅读体系，不复制幻灯片尺寸。这是所选规则的 CSL 适配，不执行任意 LaTeX 宏或完整 biblatex 样式扩展。

`.bib` 仍属于忽略的静态资源类型：仅明确读取根部 `ref.bib`，拒绝符号链接和超过 2 MiB 的文件；文献条目只投影必要书目字段并经过 HTML 消毒，不输出 abstract、note、file 或整份数据库，不让 frontmatter 指定任意 bibliography/CSL 路径、网络 URL 或 `noCite` 全量输出。`citekey` 元数据不会自动把文章变成一次引用。搜索仍只消费作者正文，不因 bibliography 追加未写入正文的文献元数据；既有发布和 unlisted 边界保持不变。开发模式中根部 `ref.bib` 变化会使内容与 Astro 路由缓存失效，其他被忽略的 `.bib` 不因此开放。

正文中的行内标签（如 `#CCF`、`#主题/计算机`）与 YAML 标签使用同一套大小写敏感的身份及 UTF-8 十六进制路由。标签可包含中文、字母、数字、下划线和连字符，以 `/` 分层，但不将纯数字当作标签。只有 YAML `tags` 表示文章所属分类，参与分类徽章、标签归档、搜索的 `#标签` 筛选和图谱分类边。正文、标题和自定义摘要中的行内标签单独记录为 `tagMentions`，只提供分类页导航，不将文章归入该分类，也不产生文章链接、反向链接或图谱边；普通全文搜索仍可检索这些正文词语。仅被提及而尚无归类文章的标签保留空分类页，避免链接失效。引用或嵌入另一个文档不会把它的分类或标签提及算到宿主文章上。unlisted 内容不通过行内标签创建发现入口。

行内标签在段落、列表、表格、Callout、脚注、Markdown 标题及可见 HTML 文本中生成原生链接，外观统一复用常规标签的方框徽章：浅绿底色、边框、圆角、内边距及悬停状态，不使用普通超链接的下划线样式。行内文本已有 `#`，不再通过伪元素重复添加；桌面与移动端共享常规标签的尺寸规则。标题的历史 ID 保持不变；桌面和移动目录的整行仍用于阅读进度定位，标签文字独立链接到标签页，其余文字链接到原标题锚点。文章卡片、目录树、面包屑、最近更新、反链、友链介绍、搜索结果和预览复用同一分词规则；卡片主链接与标签链接为相邻元素，不生成嵌套 `<a>`。元数据、图谱绘制标签、图片替代文本及无交互的装饰文字仍使用纯文本。

代码、数学、URL、显式转义的 `\\#` 及已有链接的标签文字不做自动标签链接；原作者指定的链接优先。原生 HTML 经过白名单消毒，危险 URL、脚本和事件属性不会因为“编辑器里能显示”就进入公开页面。

删除线采用原生双横装饰：Markdown 的 `~~文字~~` 仍编译为语义化 `<del>`，正文中的 `<del>` 与 `<s>` 使用 `text-decoration-line: line-through` 和 `text-decoration-style: double`。不额外加粗、绘制伪元素或将文字包成不可换行的盒子，交由浏览器处理多行、字号与嵌套行内内容。全文预览复用同一 `.prose` 样式；代码中的字面 `~~` 不受影响。

这仍不是完整的 Obsidian 运行时。复杂 OFM 边界、Mermaid 渲染、其他 Bases 视图与嵌入、Canvas、查询嵌入，以及任意社区插件，都需要自己的范围与用例。当前不能把普通代码块或提示信息称为已经支持了对应功能。

## 4. 从设计原型到真正的阅读界面

早期原型用来确认阅读秩序。方向确定后，页面通过真实 Astro 路由、内容与共享组件实现，避免让静态展示和实际阅读体验成为两套不同的东西。

站点界面位于 `src/components/`，使用带类型化 Props 的 Astro 组件：阅读元信息、友链、卡片列表、目录、侧栏与图谱的静态 SVG 都直接表达 HTML/SVG 层级，由 Astro 处理文本转义。`src/ui/` 只保留有类型的数据与展示模型，包括目录树、标签分组、更新排序、阅读时长、时效性判断和图谱布局；浏览器交互仍由 `src/runtime/` 独立实现，不引入额外 UI 框架或客户端路由。`set:html` 仅保留在编译后的正文、JSON 和字体 CSS 等必要的序列化边界，不用来串联普通 UI 字符串模板。

内容策略、Markdown 节点变换与共享图谱算法同样使用 TypeScript：Markdown/HAST 节点通过判别字段收窄类型，D3 使用与当前主版本匹配的类型声明，图谱输入与模拟节点分别建模。Prettier 配置也采用 TypeScript 并纳入类型检查。浏览器运行时以 DOM 元素、事件、动画控制器和图谱载荷类型约束模块边界；网络图谱数据先从 `unknown` 校验，再交给视图。medium-zoom 的本地声明补充锁定补丁提供的 Motion 与销毁接口，不改第三方发行包的实现语言。

手写测试与测试辅助模块同样使用 TypeScript；DOM、Canvas、WAAPI 的替身在测试边界显式建模，不把这些部分实现冒充为完整浏览器环境。`allowJs` 已关闭，测试检查源码、脚本、测试及顶层配置不再混入手写 JavaScript；依赖、补丁与编译后的 JavaScript 不受此约束。这是本站的语言约定，不是 Astro 对所有项目的强制要求。

组件测试通过 Astro 的 Vite 配置和 Container 渲染真实模板，继续使用现有 Node 测试工具，覆盖转义、链接、标题层级及 DOM 交互契约；纯计算可直接单元测试。静态产物检查负责验证完整页面的组合结果，HTTP 与开发模块检查验证实际资源边界，而不是用测试用的另一套模板代替真实组件。

### 页面先为阅读服务

本站保持浅色，不跟随系统深色，也没有主题切换。品牌名称是「忘れてください」，mark 使用意为书签的「栞」，不显示 byline；favicon 沿用旧站原始 PNG。顶层导航为“主页、文章、足迹、友链、关于”，文章有自己的地址。

文章文件名标题和正文一级标题使用独立选择器，避免 `.article h1` 把正文标题当成页首大标题。文件名标题为 32px（窄屏 28px），正文一级标题为 30px（窄屏 26px），大屏不额外放大；归档等独立页面的标题保持 42px（窄屏 34px）。

窄屏（≤800px）正文二、三级标题采用自然文本流，链接、显式预览图钉和后续文字按行内内容换行，不作为独立 flex 列相互挤压。标题末尾的 `#` 锚点标识在窄屏隐藏，避免成为孤立符号；标题 ID、原生深链和目录导航保留，桌面锚点入口不变。触屏仍可通过图钉固定全文预览。

桌面采用宽正文与右侧辅助栏，窄屏改为单栏。主页右栏依次是最近更新与热力图、关系图谱、大纲；其他阅读页依次是图谱、大纲、反向链接。最近更新只显示一篇，标题与日期同排。热力图保留日期信息，不增加装饰性的说明和图例。

主页与关于直接来自内容仓库的 `index.md`、`about.md`。具体文章和目录导读显示面包屑，名称优先使用公开目录索引的标题；主页、关于和列表页不强加面包屑。

中文正文采用霞鹜文楷轻便版，英文采用 Linux Biolinum，代码优先设备上的 Monaco。阅读日期与正文同字号，颜色较浅；Biro 用于欢迎语和阅读元信息。样式以 Tailwind 的 tokens、工具与语义组件为主，不启用 Preflight，不扫描内容库提取 CSS，也不把 Tailwind 本身当作性能优化。

### 目录不是另一种标签列表

归档按真实目录递归分组，不按 tag 复制文章。一级目录没有额外边框，卡片保留圆角与层次；卡片显示标题、摘要、创作日期和标签，不使用封面。摘要优先取 description，否则取正文首句。

卡片组支持鼠标悬停展开、移开收起，同时保留键盘与触屏路径；没有独立的展开按钮。标签页复用卡片，桌面双列、窄屏单列。标签较多时调整日期位置，而不是让摘要区域不断挤压。

MoC 是“内容地图”笔记，也是目录的入口。构建模块把一级目录与唯一匹配的 `*-toc.md` 对应：只接受公开、可发现的页面；同名歧义不猜测，深层或未匹配的 MoC 仍按普通文章处理。

映射成功后，目录标题成为通往原 MoC 的原生链接，不再额外摆一张重复卡片。MoC 的原页面、评论、搜索与图谱身份都保留。这样，每篇内容在归档里只有一个入口，而不是靠隐藏文章来消除重复。

当前页首是“142 则笔记，48 个主题，慢慢生长。”：138 张卡片加 4 个 MoC 标题入口，主题数只计显式标签，不把补出的祖先标签也算进去。

### 更新顺序与目录顺序分开

`/articles` 保留目录优先的归档，`/updates` 则只按每篇公开可发现文章的 `lastmod`（缺失时用 `date`）倒序排列，同日按来源路径稳定排序。更新页复用文章卡片，但采用单列 card-list，不折叠为堆栈，卡片日期明确标为最近更新。页首仅保留标题与数量说明，不额外放置目录切换链接。主页侧栏的「最近更新」标题可直达此页，不在顶部增加一个导航项；该页进入 sitemap，不改变文章本身的地址。

### 足迹：地图展示，构建期查询

`/journey` 读取 `src/site.config.ts` 明确指定的 `My Journey.base` / `My Journey` 视图，只支持 `type: map`，不增加 table、cards、list、board 或 Markdown Base 嵌入。页面只保留地图，不显示笔记/地点总量或独立笔记列表；文章入口留在地点弹窗内。没有 JavaScript 时说明地图需要 JavaScript，不改成另一份归档。

YAML 校验、全局与视图筛选、公式计算在构建期完成，直接复用 `@quartz-community/bases-page@1.0.0/compiler`，不移植 Quartz 的页面组件或浏览器解释器。公式按依赖顺序计算，循环引用、未知函数、非法配置和非 map 视图给出诊断与明确错误状态；不把配置错误伪装成没有公开地点。`order` 是展示属性顺序，不借用 Quartz resolver 将它当作排序条件。完整 frontmatter 仅留在构建期上下文，浏览器只收到地点、文章身份/地址、图标、颜色和地图选项的显式投影；查询及 `asFile()` 的属性来源都限于 D。地图的 `file.hasTag()` 包含当前公开笔记的 YAML 标签与自身行内提及，不改变本站标签归档和图谱的分类规则。

坐标接受 `lat, lng` 字符串与列表，保留零坐标，要求有限数值、纬度 ±90 与经度 ±180；非法地点诊断后跳过。相同坐标共用标记，弹窗保留每篇笔记的原生链接、图标和颜色，不让重叠标记遮住其余文章。Lucide 图标为本地 SVG，当前公式涉及的七种图标直接打包，未知名称回退到 map-pin，不请求默认远端 marker 图像。

地图封装采用 `astro-leaflet@1.12.0` / Leaflet 1.9.4。支持坐标、marker 属性引用、center、defaultZoom、minZoom/maxZoom、mapHeight 与 HTTPS 栅格 mapTiles；未指定底图时使用 OpenStreetMap，并保留版权链接。矢量 style URL 明确拒绝，不能把这一栅格方案称作 Obsidian Maps 默认 OpenFreeMap 的等价实现。高 DPI 下，带 `{r}` 的服务使用原生高清瓦片；其他服务启用 Leaflet retina 路径，以更高一级的瓦片提高像素密度，并校正最大缩放层级，OSM 请求不超过 19。后者可能增加瓦片数量，仍受栅格源分辨率与标注样式限制，不等于矢量底图。

地图区域内的双指捏合缩放由地图接管：触屏使用 Leaflet 原生 touchZoom 和局部 touch-action 约束，触控板的 Ctrl+wheel 与 WebKit GestureEvents 经公开地图 API 即时更新缩放，支持小数缩放并限制在配置范围内，不追加惯性、回弹或时间插值。普通滚轮与触控板双指滚动仍用于页面或弹窗滚动；地图之外的网页缩放、键盘缩放和 viewport 可访问性设置不改变。WebKit 的触屏手势不重复应用触控板缩放，销毁和页面隐藏清理手势状态，页面退出释放事件监听。

点击或键盘打开地点弹窗时，通过共享 Motion 数值过渡平移对焦，保持当前缩放；数值适配器随地图引擎加载，使用同一 Motion frame 时钟和单调时间做 ease-out cubic 插值，不再加载完整数值 animate 或异步动画后端。弹窗根据实际视口约束宽高，长内容使用 Leaflet 自身的滚动区。通常将标记放在地图中心，必要时按实测弹窗边界做最小偏移，避免裁切。新弹窗、拖动、缩放、关闭和销毁可取消旧对焦，运行时 reduced motion 或后台切换直接完成目标；窗口尺寸变化只做即时可见性校正，不强加第二段动画。原生 Leaflet 缩放、淡入、惯性与平移动画关闭，避免同时运行两套时钟。

路由脚本先延迟导入轻量控制器，控制器再按可见性加载地图引擎；完整数据投影校验先于地图实例激活。组件补丁把 Leaflet CSS 暴露为 URL 资源，避免 Astro 将动态样式提前放进页面 head；控制器等待样式加载成功才挂载地图，失败可重试，退出时取消等待并移除所属样式链接。延迟 custom element 不会仅因模块到达就创建地图；断开与页面退出释放实例，BFCache 恢复可重新激活。Leaflet 的 CSS 补丁关闭原生 transition。静态资源检查只允许三个原始依赖 sprites，并校验文件名与字节哈希；它们可能内联在样式中，不是文章图片的优化或转码产物。

### Markdown 友链与构建侧朋友圈

`/link` 保留原笔记与评论身份，兼容「简介 | 链接」旧表格，并支持可选的名称、头像、RSS 列；源文件在 Markdown 阅读器里仍是普通表格，站点中转换为友链卡片。简介是对朋友本人的介绍，直接使用表格文字，不提取网站描述；显示名可由姓名、昵称或名称列指定。表格之外的正文保留。头像仅使用明确填写的地址，由浏览器直连；缺失时用名字首字，不寻找头像或 favicon。友链页不再重复展示文章抬头、元信息或卡片分组标题，只在订阅列表上方显示一个一级标题「近况」。每条近况采用「作者－标题　日期」的单行布局，日期靠右，行内上下间距为 8px；窄屏和长文本通过省略号收敛，仍保留完整的链接文本和提示，不换成双行。

朋友圈在构建侧聚合 RSS/Atom，不要求浏览器跨域读取，也不把第三方正文 HTML 注入页面。来源是公开友链表格，不扫描未发布笔记；只同步明确填写的 RSS 地址，缺列、空白或 `-` 即没有订阅，不访问首页或猜测 feed 路径。每源最多保留 12 篇，汇总按日期倒序、URL 去重，页面合计最多显示最新 10 篇。已配置的失败源可复用同一地址的已验证旧快照，首次失败保持空状态；删除地址后停止请求并移除该源的文章，旧自动发现快照不再有效；读取只允许公开 HTTPS，DNS 地址在校验后固定，拒绝私网与 XML DTD。

友链近况采用构建时的静态快照，不需要定时刷新。Pages 发布工作流仅在 `main` 收到推送时触发一次，不配置定时、手动或串联工作流触发器；构建和部署是同一次运行中通过 `needs: build` 衔接的两个作业。公开订阅快照单独缓存，不缓存私有内容源或 Astro 编译产物。静态页面保留该次构建结果，不承诺实时更新，实际订阅可用性和缓存状态如实展示。格式和同步命令见 [友链说明](friends.md)。

### 交互不能抢走阅读位置

大纲不仅高亮当前标题，还会让被裁切的活动条目重新可见：先调整内部目录滚动区，再检查外层侧栏或移动弹窗。这里采用即时、最小的可见性补位，不滚动正文、不抢键盘焦点。

链接预览保留原生 `<a>` 导航，通过 Floating UI 处理边缘定位；悬浮或键盘聚焦后按需请求文章 HTML，旁边的图钉用于固定可滚动的全文预览，窄屏也可通过图钉打开。悬浮层有独立阅读滚动区，不截断正文；章节链接打开后即时定位到对应标题，脚注和内部锚点只滚动预览，不改变宿主文章的地址或阅读位置。保留打开原文、取消固定、关闭与 Escape，显式打开时焦点进入预览，关闭后恢复触发控件。

全文提取适配 [Quartz 的 MIT popover 组件](https://github.com/jackyzha0/quartz/blob/6dd772bf00459fe5165140e4e756e2b3096686e8/quartz/components/scripts/popover.inline.ts)，署名见 `LICENSES/quartz-popover.txt`。已核验的 Astro 候选中，[astro-embed LinkPreview](https://astro-embed.netlify.app/components/link-preview/) 是元数据卡片，[astro-link-preview](https://github.com/cijiugechu/astro-link-preview) 是外链截图，[astro-prefetch-ai-brief](https://github.com/bhubbard/astro-prefetch-ai-brief) 是短摘要，都不提供可滚动全文。因此复用 Quartz 的 HTML 提取思路和本站已有 Floating UI，而不引入截图、AI 或额外 UI 框架。

只有公开可发现文章进入预览目录；请求限制在同站原生文章地址，不跟随重定向到其他内容。显式 `data-preview-content` 标记文章抬头、正文及友链展示，不带入页面导航、图谱、评论或站点控制器。导入前移除可执行元素、事件属性与预览按钮，重写相对资源地址、DOM ID、脚注和 MathJax SVG 引用，避免与宿主页冲突。Floating UI 定位引擎、正文提取模块与文章 HTML 都只在触发预览后加载，不增加每个页面的全文载荷；迟到的定位结果不能移动已关闭或换目标的预览，定位失败也可重试。成功 HTML 最多缓存八篇；关闭、页面退出或切换目标会取消请求，迟到的旧请求不能覆盖当前文章。加载错误和超时提供重试及原文链接，不将错误响应缓存成永久结果。

页面导航采用渐进式反馈，不额外引入客户端路由器：新页面在 `pageshow` 时轻微淡入与上移，后退/前进（包括 BFCache 恢复）只淡入，不扰动浏览器恢复的滚动位置；锚点切换短暂强调目标。`pagehide` 和销毁会取消效果，无脚本仍是普通链接，不拦截修饰键、新标签页、下载或焦点行为。运行时切换 reduced motion 会立即停止并恢复样式。

最近更新（updates）、标签结果和友链页的卡片显式启用悬停强调：保持布局不变，仅放大到 1.01 倍，由共享 Motion 在 0.2 秒内过渡；移出时平滑恢复。键盘聚焦卡片内链接时提供同样强调，焦点在同卡片链接间移动不闪烁；触屏指针和无 hover 能力设备不触发悬停效果。reduced motion 禁用放大，运行时偏好改变或页面隐藏即时取消并还原；页面退出清理监听和变换，BFCache 恢复可重新启用。普通卡片默认不启用，归档堆叠保持原有变换控制器，不叠加此效果。

所有有时长的自有动效都经过共享 Motion，包括卡片、大纲标记、预览、图谱、导航反馈与灯箱。直接拖动坐标、滚动进度和即时可见性校正不是时间插值，不为了统一工具而人为加动画。取消、销毁和运行时 reduced motion 是同一份交互契约的一部分。

## 5. 图谱：复用成熟力学，但不照搬整个插件

局部图回答“这篇笔记直接联系着谁”，全局图回答“整个知识库如何连接”。两者不能只用同一张图换一个尺寸。

### 严格的一跳局部图

局部图只包含当前笔记、直接出链/反链和本页 YAML 显式分类标签，正文里的标签提及不参与图谱。不自动加入邻居的标签、标签祖先、同标签文章或二跳笔记；保留这些节点之间真实存在的边，不编造关系。

初始布局在服务端用 D3 计算 180 ticks，再生成 300×250 的 SVG。当前笔记初始位于 `(150,125)`，普通节点半径 5.5，当前点 7，命中圈 12。局部图不显示说明、缩放工具栏和图例，只保留全局图入口；无脚本时仍可使用节点链接。

交互时可以拖动页面、标签和当前节点，**不能拖背景平移整张图**。滚轮/双指缩放保留，双指中点移动不平移；聚焦节点时方向键移动该点，Enter 正常导航，Home/0 恢复初始位置与视口。

**拖动只是临时位移，图心不变**。当前笔记松手后平滑回中心，邻居重新平衡，不要求每个点回到拖前的精确坐标；缩放不被重置。这样既能探索连线，也不会因一次拖动失去当前笔记的视觉中心。

实现继续使用 D3 的向心力：一个独立粒子带动当前锚点返回，与邻域模拟共享 Motion 时钟，不手写补间。重新抓取可中断返回，后台暂停，reduced motion 直接求终态，销毁后不再更新。懒加载晚到时，也不能把已经拖动的坐标误认为图心。

### 自然分布的全局图

全局图只消费 D，以公开可发现的现有文章、真实引用和显式分类关系形成网络。当前预设为 **Tags ON、Attachments OFF、Existing files ON、Arrows OFF**。标签必须保留，不作为布局调参时可关闭的选项；标签节点、成员关系和父子关系均进入力学求解与 JSON 输出，空心双环和图例继续区分标签与文章。附件不作为笔记节点，不为不存在或未公开的引用建立占位节点。真实文章即使没有连接也保留，连线不画箭头。标签页、搜索及局部图的显式标签关系不受影响。使用 Canvas 绘制，模块与数据在打开或交互意图时才准备；不在首屏抓取完整图数据。

核心来自 `starlight-site-graph@0.5.0` 的 D3 force/drag 适配，保留 MIT 署名；不是把 Starlight、Pixi、GSAP 和预取体系整体搬进来，也不是重写力学引擎。早期插件配置合并遇到问题后，继续修补和验证数据消费，比看到一次报错或一个较大的包体就放弃复用更合理。

全局布局强调由真实引用和分类关系形成的团簇，不再用额外弱化的标签连接和不同类型的目标距离组织区域。不添加虚构边、随机抖动、光晕或持续闪烁。统一参数位于 `src/graph/global-style.ts`，构建期布局与客户端重热使用同一份配置；局部图不受影响。

| 全局参数 | 预设值 | 本站作用与 D3 映射 |
| --- | --- | --- |
| Center `force.center` | 0.42 | 直接作为 X/Y 向心强度，约束断开的节点，避免无限散开。 |
| Repel `force.repel` | 7.5 | 换算为排斥强度 `−100 × repel = −750`；保留全范围排斥，但降低分离力度，避免把连接持续拉长。 |
| Link `force.link` | 0.82 | 真实连接使用固定拉力 0.82，不再按关系类型或节点关联边数进一步削弱。 |
| Distance `force.distance` | 100 | 所有连接的目标长度为 100 布局单位；与降低排斥配合收紧间距，实际长度仍由各项力共同决定。 |
| Text fade `textFade` | 0.75 | 全局普通标题在缩放超过 0.75 后渐显，1.425 起完全显示，不是恒定的 75% 不透明度。 |
| Node size `nodeSize` | 0.85 | 保持基础半径 6、增长系数 4、上限 30 的度数曲线，整体缩小 15%，不改变普通节点与枢纽的大小比例。 |
| Link thickness `linkThickness` | 0.5 | 连续实线保持 0.5 屏幕像素，不随缩放成比例变粗或消失。 |

以上数值是本站显式适配的控制单位，不声称与 Obsidian 内部引擎一比一等价。[Obsidian 文档](https://help.obsidian.md/plugins/graph)说明了四项力的作用，但未规定到 D3 的数值映射；排斥的 `−100` 换算参考 [Quartz 实现](https://github.com/jackyzha0/quartz/blob/d25a6eabf96751ffca56f8a8139272def7a65041/quartz/components/scripts/graph.inline.ts#L168-L172)。Center 直接使用 D3 X/Y 向心约束；仅用 D3 `forceCenter` 平移质心不会约束断开的节点间距，也不是 Obsidian 文档所说的紧凑度控制。

全局节点按独立邻居数增长，包括文章和标签邻居；互链和重复边不重复计数，自环不计：

```text
radius = 0.85 × min(30, 6 + 4 × sqrt(degree))
```

度数 0、1、4、16 的半径分别为 5.1、8.5、11.9、18.7 布局单位，到度数 36 才达到 25.5 的上限，避免常见连接数提前饱和。半径调整需要同时核对默认全图适配后的屏幕大小与差异，而不只统一放大所有圆点；碰撞、点击命中、标题偏移均使用相同半径。连线在节点圆周处截断，不穿过空心标签；拖动造成的重叠或重合节点不绘制反向或无效线段。当前节点用颜色区分，不突破半径上限。碰撞额外留白保持 3，冷却系数保持 0.03，求解预算保持 240 ticks。局部图仍使用原来的 5.5/7 半径和 1–1.9 倍缩放显字规则；两种图的当前、悬停、聚焦以及局部拖动节点保留标题反馈。完整名称仍可访问。

全局保留图例、必要的缩放/复位/关闭与错误状态，不显示页面/标签列表或操作说明。全局背景可以平移，节点拖动带动邻域；这与局部图的禁止背景平移是两个明确约定。

D3 自身的模拟时钟停止，由 Motion 有界推进，重热后全局最多 240 ticks，局部仍为 180 ticks。隐藏页面暂停，reduced motion 直接求终态，销毁取消剩余调度；全局配色和局部图原有交互保持不变。源码对照也揭示了边界：[starlight-site-graph](https://github.com/fevol/starlight-site-graph/blob/fed9ce0b3aa160255a673aa76aeea17166dcceb9/packages/starlight-site-graph/components/graph/simulator.ts) 与 [Quartz](https://github.com/jackyzha0/quartz/blob/d25a6eabf96751ffca56f8a8139272def7a65041/quartz/components/scripts/graph.inline.ts) 都在松手时解除 `fx/fy`，但并不保证每个点恢复旧坐标。当前笔记精确回图心是本站补充的约束，不是虚构的插件开关。

## 6. 图片与字体：布局正确不代表资源正确

### 图片适配是显示尺寸，不是构建期转码

正文图片保留原始 URL，由浏览器直接请求 OSS；本地附件沿用已有允许集合与 `media/` 路由。构建不下载远程图片、不探测其元数据，也不调用 `getImage()` / Sharp 生成 WebP、srcset 或图片代理。这样 OSS 的瞬时网络故障不会阻止站点构建，但访问页面时仍依赖图片源的可用性。

尺寸适配限定在 HTML/CSS：图片最大宽度不超过正文，自动高度保持自然比例；OFM 的 `|400`、`|400x300` 以及 HTML 宽高被视为显示边界，而不是裁剪或转码请求。未知原始尺寸时不编造固有宽高。保留 alt、图注、GIF 与作者已有链接，使用原生延迟加载和异步解码。

测试以拒绝网络请求的环境验证原始 URL 不变；静态检查拒绝重新出现的生成图片及 srcset，HTTP 检查读取页面中的 OSS URL 而不请求第三方图片。这些检查不宣称原始图片减小了下载量，也不代替浏览器端显示验证。

原图放大采用 medium-zoom 的 pure 入口。保留成熟库的几何和克隆机制，通过锁定补丁把开合交给 Motion，补齐关闭中断、加载超时、焦点与清理。已有作者链接不劫持，修饰键和无脚本路径仍可打开原图。

### 缺字不是补两字就结束

旧的小字体子集没有覆盖“旅途还在继续”中的部分字符，静态字体又被错误声明成可变字重。只补两个字，会把问题推迟到下一篇文章。

现在字体输入统一放在 `assets/fonts/`：

| 输入 | 用途与处理 |
|---|---|
| LXGW WenKai Lite 1.522 Regular | CJK，固定 OFL 输入，生成分片 |
| Linux Biolinum O Regular / Bold | Latin，固定 OFL 输入，分别生成分片 |
| Biro Script Plus 原始 WOFF2 | 作者提供，保持 284,772 B 与 OpenType，不重新子集化 |

CJK 与 Latin regular 如实声明 400，Latin bold 声明 700；没有额外提供真正的中文粗体，明确需要粗体的中文仍可能由浏览器合成。足迹页使用正常字重，而不是借系统缺字回退形成混杂样式。

字体准备使用独立的 `notes-font-preparation` 集成，在来源校验/分片准备前打印开始信息，完成后报告耗时，失败时保留原始错误；不再把这项工作挂在内容监听集成名下。预览已有产物时跳过字体准备，缓存校验和按需生成行为不变。

字体制作参考 [astro-navfolio 的 UI 子集脚本](https://github.com/dodolalorc/astro-navfolio/blob/v1/scripts/fonts/subset-ui-font.ts)。流程是：固定源文件及 SHA256，使用锁定的 FontTools/Brotli，扫描 UI 源目录生成优先子集，再生成完整源字表的 Unicode 分片。完整覆盖不依赖当前文章里恰好出现了哪些字符。

这保留了源字体支持的 25,598 个 CJK 字符、2,400/2,539 个 Latin 字符。CSS 的声明顺序与实际 cmap 一起验证，避免某个 unicode-range 声称接管字符却没有字形。源字体之外的 Unicode 仍需要系统回退；完整 cmap 也不等于已经验证所有跨片 shaping 或浏览器字体选择。

字体分片不是免费优化。当前 OFL 产物为 167 个 WOFF2、7,626,524 B，其中三个 UI 片合计 131,756 B；最大一片 92,424 B。加上原始 Biro 为 7,911,296 B。分片重复表、压缩边界及 UI 优先覆盖都会增加存储，**UI 字节不等于一页的字体下载量**。

生成目录只需要当前 CSS/manifest 引用的 167 个 WOFF2，加上 CSS 和清单共 169 个文件。分片分别承载不同字重与字符范围；UI 与完整字表的部分字符重叠是加载策略，不能简单按字符重复去删除，更不能为了减少文件数变成首屏加载完整大字库。

`fonts:clean` 是显式维护命令：先检查清单、CSS、文件哈希与路径，再删除无引用产物；不在 dev/build 中自动清理旧地址，避免破坏正在使用旧 CSS 的页面。清理时不与字体生成并行，旧页面应重新打开。

Biro 直接使用原始 WOFF2，不参与 OFL 子集流程。它不属于 OFL，使用时需要相应的 Webfont 许可。

## 7. 真正的开发服务，也是验证对象

有一次，全局图 JSON 和入口脚本都是 200，页面却仍然打不开图。原因在入口引用的 Vite 预优化依赖：它们返回 `504 Outdated Optimize Dep`。只检查 JSON，或者在 Node 中从 node_modules 重新打包，都可能绕过这条真正失败的路径。

现在开发缓存按命令、端口和 base 隔离，避免并行开发和验证进程互相覆盖预优化依赖。内容快照与派生数据按版本共享，失败允许重试；内容更新不仅使快照失效，也通知 Astro 清理路由 props，避免拿旧页面数据重新渲染。

测试覆盖分成几层：

- Node fixtures 检查发布边界、OFM、链接、图谱、交互状态与清理。
- 编译和静态产物检查验证路由、片段、资源、字体哈希、原图 URL、favicon 与预算。
- 独立 HTTP 检查验证深链、资源 MIME、二进制与 404。
- 开发检查读取真实 Vite ESM 和首页 SVG，通过默认懒加载入口在 Node DOM/Canvas 边界执行图谱逻辑，检查松手回中心、暂停恢复与 reduced motion，而非绕过实际模块请求。地图另检查实际页面投影与 Vite 的 Leaflet/Motion/样式依赖编译；Node 替身覆盖居中几何、高 DPI 选项、取消和 reduced motion，不宣称运行了真实地图布局或瓦片请求。

这些检查不覆盖真实浏览器的渲染、输入与辅助技术行为。LCP、INP、帧率、触屏和屏幕阅读器体验需要各自的实测，不能从 Node 或 HTTP 检查中推断。

生产分包将共享 Motion 和 Vite preload helper 独立于站点入口，避免地图因共享时钟或加载辅助函数而依赖搜索、预览和图谱；站点入口与布局脚本合并，定位引擎保持延迟加载。资源预算也只回答有限问题：页面入口及静态依赖 JS gzip 不超过 20 KiB，HTML 引用的共享/路由 CSS gzip 合计不超过 12 KiB；可见时按需加载的地图 JS 及其静态/动态依赖完整链路另限 80 KiB，延迟地图 CSS 另限 8 KiB，同时报告全部 CSS 总量。地图位于首个视口时仍会很快请求延迟资源，入口预算不等于整页实际传输量。UI 字体不超过 256 KiB、单片不超过 128 KiB、完整 OFL 存储不超过 8 MiB，Biro 单列。旧的“其他字体总量 256 KiB”已被完整字表方案替代，不能继续声称满足它。没有用包体较小证明“更快”，也不把静态样本的历史性能分数套到真实站点上。

测试还需要贴合交互意图。例如，局部图的回归既要验证节点可以拖动，也要验证当前节点松手后回到固定图心；只验证前半段，无法保证完整行为。

源代码使用 Prettier 与官方 Astro 插件统一格式，范围是 `src/`，排除生成字体，不触碰独立内容仓库。Astro 模板的格式化采用 JSX 空白语义，与 Astro 7 编译配置一致；格式检查加入 `validate`，但不代替类型和行为测试。

## 8. 一个可以继续生长的博客

当前内容生成 205 个 HTML 页面：145 个公开阅读页、56 个标签页，以及归档、最近更新、足迹和 404。静态输出让内容编译与页面交付分开：构建环境需要源码、锁文件、字体输入和固定内容版本，静态服务器只需要 `dist/`。内容源库、构建缓存和原始 TTF/OTF 不属于静态发布目录。

GitHub Pages 采用独立的构建与部署 job，结构参考 [Astro 官方部署方案](https://docs.astro.build/en/guides/deploy/github/)和 [Navfolio 的工作流](https://github.com/dodolalorc/astro-navfolio/blob/v1/.github/workflows/deploy-pages.yml)。本站显式固定 Node、Bun、uv 和字体依赖，冻结安装锁文件；读取私有内容所需的凭据只用于检出，且不让内容分支自动前移。类型检查、测试、构建、静态产物与本地 HTTP 检查全部通过后，才上传 `dist/` 并交给具有 Pages/OIDC 权限的部署 job。只有 `main` 可部署，不缓存内容派生输出；自定义域名与评论身份仍由原站点配置决定。具体配置见[部署工作流](../.github/workflows/deploy.yml)。

这套实现仍有明确的能力范围：地图之外的 Bases 视图与嵌入、矢量底图、Mermaid 渲染、更完整的 OFM 与历史别名重定向，都还有继续完善的空间。新增能力应接入同一套文档身份、发布选择与资源管线，而不是再建立一套互相矛盾的解析规则。

最后留下的不是一套更庞大的框架，而是一组更清楚的职责：内容仍由自己的笔记库决定，成熟库解决成熟问题，本站代码只承担真正需要自己决定的部分。
